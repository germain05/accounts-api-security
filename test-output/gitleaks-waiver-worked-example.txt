Worked example: the waiver mechanism running against this very repository.
Reproduce with the commands shown; nothing here is hand-written output.

$ rm -f .gitleaks.toml   # no waiver-derived allowlist present
$ gitleaks detect --source . --no-git --redact
[90m2:36PM[0m [32mINF[0m scan completed in 95.8ms
[90m2:36PM[0m [31mWRN[0m leaks found: 1
  FINDING  k8s/externalsecret.yaml:86  rule=kubernetes-secret-yaml

$ python3 scripts/waiver_check.py check --verify-signatures
OK: 4 waiver(s) valid, signed and unexpired (0 expiring within 7d).

$ python3 scripts/waiver_check.py generate
generated ignore files from 4/4 active waiver(s); 0 expired waiver(s) deliberately NOT suppressed

$ cat .gitleaks.toml
# GENERATED by scripts/waiver_check.py — do not edit, do not commit.
[extend]
useDefault = true

[allowlist]
description = "Derived from waivers/waivers.yaml (CODEOWNERS + cosign gated)"
regexTarget = "line"
regexes = [
    '''DE89370400440532013000|GB29NWBK60161331926819''',
    '''kind: (SecretStore|ExternalSecret|SecretProviderClass)'''
]

$ gitleaks detect --source . --no-git --config .gitleaks.toml --redact --exit-code 1
[90m2:36PM[0m [32mINF[0m scan completed in 94.4ms
[90m2:36PM[0m [32mINF[0m no leaks found
  exit code: 0

The suppression exists only because SEC-2118 is present, signed by an approver
in APPROVERS.yaml, and unexpired. Delete the waiver, or let 2027-03-03 pass,
and .gitleaks.toml regenerates without that pattern and the finding returns.
